## การเปิดระบบ

### 1. เปิด Backend

ตรวจสอบว่า PostgreSQL ทำงานและตั้งค่า `backend/.env` แล้ว จากนั้นใช้คำสั่ง:

```powershell
cd backend
go run ./cmd/server
```

Backend ใช้ `http://localhost:8080` หากไม่ได้กำหนด `PORT` ค่าอื่น

### 2. เพิ่มข้อมูลจำลอง (ทำครั้งแรก)

ฐานข้อมูลต้องมี Concert รหัส `CC0001`, `CC0002` และ `CC0003` ก่อน:

```powershell
cd backend
go run ./cmd/seed-management --apply
```

Seeder จะเพิ่มรอบการแสดง, Publication, Zone, Seat และ Ticket โดยไม่สร้าง Booking และไม่เขียนทับข้อมูลที่มีอยู่

สามารถดูรหัส Ticket สำหรับทดลองลงทะเบียนใน pgAdmin ด้วยคำสั่ง:

```sql
SELECT t.ticket_id, t.status_ticket, c.concert_name, z.zone_name,
       s.seat_row, s.seat_column
FROM tickets AS t
JOIN seats AS s ON s.seat_id = t.seat_id
JOIN zones AS z ON z.zone_id = s.zone_id
JOIN concerts AS c ON c.concert_id = s.concert_id
ORDER BY t.ticket_id;
```

### 3. เปิด Frontend

```powershell
cd frontend
npm install
npm run dev
```

เปิดเว็บที่ `http://localhost:5173`

## คู่มือระบบลงทะเบียนเข้างาน

เข้าใช้งานผ่านเมนู **ลงทะเบียนเข้างาน** หรือ URL:

```text
http://localhost:5173/event-registration
```

### วิธีลงทะเบียนบัตร

1. กรอกรหัส Ticket จากฐานข้อมูล สามารถกรอกเป็นตัวเลข เช่น `1` หรือรูปแบบ `TK-000001`
2. กด **ตรวจสอบและลงทะเบียน**
3. ระบบตรวจข้อมูลจากตาราง `tickets`, `seats`, `zones` และ `concerts`
4. ถ้าบัตรถูกต้อง ระบบจะ:
   - สร้างข้อมูลในตาราง `gate_check_ins`
   - ผูก `tickets.gate_id` กับรายการเช็คอิน
   - เปลี่ยน `tickets.status_ticket` เป็น `checked_in`
5. หากสแกนบัตรเดิมอีกครั้ง ระบบจะแสดงว่า **บัตรนี้ถูกใช้ไปแล้ว** พร้อมเวลาเช็คอินเดิม
6. หากไม่พบบัตร ระบบจะแสดงว่า **ไม่พบบัตรนี้ในระบบ**
7. กรณีบัตรใช้แล้วหรือไม่ถูกต้อง สามารถกด **ติดต่อผู้จัดการ** ระบบจะบันทึกเหตุการณ์ใน `emp_activity_logs`

การลงทะเบียนใช้ Transaction และล็อกแถว Ticket ขณะตรวจสอบ เพื่อป้องกันการสแกนบัตรใบเดียวกันพร้อมกัน

### Registration API

| Method | Endpoint | หน้าที่ |
|---|---|---|
| `POST` | `/api/registration/check-ins` | ตรวจ Ticket และลงทะเบียนเข้างาน |
| `POST` | `/api/registration/issues` | บันทึกการแจ้งปัญหาให้ผู้จัดการ |

ตัวอย่าง Request:

```json
{
  "ticketCode": "TK-000001"
}
```

## คู่มือระบบวางแผนการจำหน่ายบัตร

เข้าใช้งานผ่านเมนู **จัดการรายการคอนเสิร์ต** หรือ URL:

```text
http://localhost:5173/search-concert
```

### หน้ารายการคอนเสิร์ต

- โหลดรายการจากตาราง `concerts`
- ค้นหาด้วยชื่อคอนเสิร์ตหรือศิลปิน
- กรองตามสถานะคอนเสิร์ต
- กดไอคอนแก้ไขเพื่อเปิดรายละเอียด

### แท็บข้อมูลทั่วไป

- แสดงข้อมูลจาก `concerts`
- เป็นข้อมูลอ่านอย่างเดียว ไม่สามารถแก้ไขจากหน้านี้

### แท็บรอบการแสดง

- ลำดับรอบ เวลาเริ่ม และเวลาจบมาจาก `performance_schedules`
- วันที่แสดง เวลาเปิดประตู และสถานะมาจาก `concerts`
- เป็นข้อมูลอ่านอย่างเดียว

### แท็บการเผยแพร่

- สามารถแก้คำอธิบาย รูปภาพ และวันเวลาการเผยแพร่ได้
- บันทึกลงตาราง `publications`
- วันที่ปิดการจองต้องไม่อยู่ก่อนวันที่เปิดขาย
- วันที่นำออกจากหน้าเว็บต้องไม่อยู่ก่อนวันที่นำขึ้นหน้าเว็บ

### แท็บผังที่นั่ง

1. เพิ่ม Zone แบบสี่เหลี่ยม วงกลม หรือสามเหลี่ยม
2. ระบุชื่อ สี ราคา ประเภทบัตร และจำนวนที่นั่ง
3. ปรับความกว้างและความสูงด้วยแถบเลื่อน
4. ลาก Zone และวัตถุไปยังตำแหน่งที่ต้องการ
5. ดับเบิลคลิก Zone เพื่อแก้ไขเก้าอี้แต่ละตัว
6. กด **บันทึกผังที่นั่ง**

ข้อมูลจะถูกจัดเก็บดังนี้:

- `zones` — รูปร่าง สี ตำแหน่ง ขนาด และชื่อ Zone
- `seats` — แถว คอลัมน์ สถานะ และตำแหน่งเก้าอี้
- `tickets` — ราคาและ Ticket ที่ผูกกับแต่ละ Seat
- `concerts.layout_objects` — เวที ข้อความ เส้น ลูกศร และวัตถุประกอบ
- `seats.flowchart` — ภาพ PNG ของผังรวม โดยเก็บภาพเดียวกันใน Seat ทุกแถวของคอนเสิร์ต

ระบบไม่อนุญาตให้ลบหรือแทนที่ Seat ที่มี Booking แล้ว และจะตอบกลับ `409 Conflict`

### Venue Seat API

| Method | Endpoint | หน้าที่ |
|---|---|---|
| `GET` | `/api/venue-seat/concerts` | อ่านรายการคอนเสิร์ต |
| `GET` | `/api/venue-seat/concerts/:id` | อ่านข้อมูลทั่วไป รอบการแสดง และ Publication |
| `PUT` | `/api/venue-seat/concerts/:id/publication` | บันทึกข้อมูลการเผยแพร่ |
| `GET` | `/api/venue-seat/concerts/:id/layout` | โหลดผังที่นั่ง |
| `PUT` | `/api/venue-seat/concerts/:id/layout` | บันทึกผังที่นั่ง |
| `DELETE` | `/api/venue-seat/concerts/:id/layout` | ล้างผังที่นั่งที่ยังไม่มี Booking |
