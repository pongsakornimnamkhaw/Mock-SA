# Spec: ตั๋วหน้า "บัตรของฉัน" เป็นรูปทรงตั๋วจริง สีโทนเดียวกับโปสเตอร์คอนเสิร์ต

## ปัญหาปัจจุบัน

การ์ดตั๋วในหน้า `บัตรของฉัน` (`/my-tickets`) เป็นกล่องสี่เหลี่ยมขอบประสีฟ้า
(`frontend/src/pages/Customer/Account/index.tsx:286-327`) ที่มีแค่ QR Code + รหัสตั๋ว + ที่นั่ง

- ไม่มีอะไรบอกว่านี่คือ "ตั๋วเข้างาน" นอกจากข้อความ — หน้าตาเหมือนกล่องข้อมูลทั่วไป
- สี (`#fbfcfe` พื้น, `#90caf9` ขอบประ, `#11366b` ตัวอักษร) ไม่เกี่ยวกับโปสเตอร์คอนเสิร์ตของงานนั้นเลย
  ทั้งที่หน้ารวมคอนเสิร์ตแสดงโปสเตอร์โทนมืด-นีออนอยู่ ทำให้ตั๋วดูหลุดจากงานที่ซื้อ
- ตั๋วทุกใบทุกงานหน้าตาเหมือนกันหมด แยกไม่ออกว่าใบไหนของงานอะไรถ้าไม่อ่านตัวหนังสือ

## สิ่งที่ต้องได้

1. ตั๋วมีรูปทรงแบบตั๋วจริงตามภาพอ้างอิงที่ผู้ใช้ส่งมา: แบ่งสองส่วนซ้าย/ขวา
   มีรอยปรุ (เส้นประ + รอยบากครึ่งวงกลมบน-ล่าง) คั่นกลาง ส่วนขวาเป็นส่วน "ADMIT ONE" ที่มี QR Code
2. สีตั๋วเป็นโทนเดียวกับโปสเตอร์คอนเสิร์ต: พื้นน้ำเงิน/ม่วงเข้มเกือบดำ + สีเน้นแบบนีออน
   (ตามที่ตกลง: เอา **รูปทรง** จากภาพอ้างอิง เอา **สี** จากโปสเตอร์ ไม่ใช่พื้นกระดาษเบจแบบในภาพ)
3. **คอนเสิร์ตต่างงานได้สีต่างกัน** โดยสีต้องตรงกับโปสเตอร์ที่การ์ดคอนเสิร์ตของงานนั้นใช้จริง
   (คอนเสิร์ตเดิมได้สีเดิมเสมอ ไม่สลับไปมาเวลารีเฟรช)
4. ข้อมูลที่ลูกค้าต้องใช้หน้างานต้องอยู่ครบเหมือนเดิม: ชื่องาน, วันแสดง, สถานที่, โซน,
   รหัสตั๋ว, ที่นั่ง, QR Code
5. กดที่ตั๋วแล้วยังเปิด Dialog ขยาย QR Code ได้เหมือนเดิม และ Dialog ใช้สีโทนเดียวกับตั๋วใบนั้น

## การตัดสินใจ

- **จับคู่สีกับโปสเตอร์ด้วยฟังก์ชันเดียวกัน** — `posterForConcert()` ใน
  `frontend/src/utils/customerConcertCard.ts` เลือกโปสเตอร์สำรองจาก checksum ของ `concert_id`
  (`fallbackPosters = [flux, pulse, celestial, starlight]`) จะย้าย logic การหา index ไปไว้ที่
  `posterIndexForConcertId()` ใน module ใหม่ แล้วให้ทั้งการ์ดคอนเสิร์ตและตั๋วเรียกตัวเดียวกัน
  ถ้าแยกกันคำนวณ สีตั๋วกับรูปโปสเตอร์จะหลุดคู่กันทันทีที่ใครแก้ข้างใดข้างหนึ่ง
- **ชุดสี 4 ชุด เรียงตรงกับ `fallbackPosters`** (index 0-3 = flux, pulse, celestial, starlight)
  โดยดูดโทนมาจากไฟล์โปสเตอร์จริงใน `frontend/src/assets/poster/`:

  | index | โปสเตอร์ | โทนในภาพ | base | stub | accent |
  |---|---|---|---|---|---|
  | 0 | flux | ม่วง/ฟูเชียนีออนบนดำอมน้ำเงิน | `#150F2E` | `#1F1547` | `#C084FC` |
  | 1 | pulse | แดงส้มโคม่วง เวทีคอนเสิร์ต | `#1A0B18` | `#2B1020` | `#FF6B5A` |
  | 2 | celestial | ทรงกลมม่วง-ชมพูบนกรมท่าเข้ม | `#0F1030` | `#191C4A` | `#818CF8` |
  | 3 | starlight | ชมพูมาเจนต้าแบบ retro sunset | `#1B0D2B` | `#28133D` | `#FF4FA3` |

- **แยกตั๋วออกเป็นคอมโพเนนต์ของตัวเอง** (`components/tickets/TicketStub.tsx`) แทนที่จะเขียนใน
  `Account/index.tsx` ต่อ — ไฟล์นั้นยาว 551 บรรทัดและคุม 4 โหมดหน้าจออยู่แล้ว การแยกทำให้
  เขียนเทสต์ตั๋วได้ตรง ๆ โดยไม่ต้อง mock `customerAccountApi` + `bookingPaymentApi` + `bookingStore`
- **คอมโพเนนต์ตั๋วเป็น presentational ล้วน** รับ props ที่ format มาแล้ว (เช่นวันที่เป็นสตริงไทย)
  ไม่ยิง API เอง ไม่ format วันที่เอง — หน้า Account ยังเป็นคนจัดการข้อมูลเหมือนเดิม
- **เปิดสี accent ออกมาเป็น `data-accent`** บน element ราก เพื่อให้เทสต์ยืนยันเรื่องสีได้แน่นอน
  โดยไม่ต้องพึ่ง computed style ของ emotion ที่เปราะใน jsdom

## นอกขอบเขต

- **ไม่ดูดสีจากไฟล์โปสเตอร์ตอน runtime** (canvas sampling) — คอนเสิร์ตที่มี `poster_data` จริงจาก
  ฐานข้อมูลจะยังได้สีจากชุด 4 สีตาม id เหมือนเดิม การดูดสีจริงต้องแก้เรื่อง CORS/async/แคช แยกเป็นงานของตัวเอง
- **ไม่แก้ checksum ที่ใช้เลือกโปสเตอร์** ถึงแม้จะรู้ว่า id ที่เป็นตัวอักษรชุดเดียวกันสลับตำแหน่ง
  (เช่น `CC0001` กับ `CC0010`) จะชนกันได้ — เป็นปัญหาเดิมที่แยกจากงานนี้ และการแก้จะทำให้
  โปสเตอร์ของคอนเสิร์ตเดิมเปลี่ยนรูปยกชุด
- **ไม่แตะหน้า `ประวัติการซื้อ` / `แก้ไขข้อมูลส่วนตัว` / `เปลี่ยนรหัสผ่าน`** ในไฟล์เดียวกัน
- **ไม่แตะ flow การออกบัตร/ส่งบัตรซ้ำทางอีเมล** — เปลี่ยนแค่การแสดงผล
