# Spec: ล็อกที่นั่งที่ถูกเลือกไปแล้ว ไม่ให้คนอื่นจองซ้ำ

## ปัญหาปัจจุบัน

ที่นั่งในหน้าเลือกที่นั่ง (`/event/:id/seats/:zone`) ไม่มีสถานะจริงบนเซิร์ฟเวอร์เลย
ลูกค้าสองคนเลือกที่นั่งเดียวกันแล้วจ่ายเงินทั้งคู่ได้ ระบบไม่มีอะไรกั้น

- `generateSeats()` ใน `frontend/src/components/SeatSelection/constants.ts:32-49` สร้างที่นั่ง
  A1–E8 (40 ที่) ในเบราว์เซอร์ และ hardcode ที่นั่งที่ "ถูกจองแล้ว" เป็นชุดตายตัว 12 ที่
  (`A3, A4, B2, B5, B7, C1, C6, D4, D8, E2, E3, E7`) — **เหมือนกันทุกคอนเสิร์ต ทุกโซน ทุกคน**
  และรีเฟรชทีก็กลับมาว่างเหมือนเดิม
- ปุ่ม "ล็อกที่นั่ง" (`handleLockSeats`, `SeatSelection/index.tsx:200-214`) กับตัวจับเวลา 15 นาที
  (`LOCK_DURATION = 900`) ทำงานใน React state ล้วน ๆ ไม่เคยไปถึงเซิร์ฟเวอร์ คนอื่นไม่มีทางรู้
- `createBooking` (`backend/internal/handlers/booking_payment.go:77-177`) **ไม่บันทึกว่าจองที่นั่งใบไหน**
  เลย — `input.Seats` ถูกใช้แค่คำนวณจำนวน (บรรทัด 105) เท่านั้น ตั๋วที่ออกมาจึงได้เลขที่นั่ง
  สังเคราะห์แบบ `ZONE-01`, `ZONE-02` (บรรทัด 217)

## สิ่งที่ต้องได้

1. ที่นั่งที่ "ถูกจองสำเร็จแล้ว" ต้องขึ้นเป็นสีเทา "ถูกจองแล้ว" และกดเลือกไม่ได้ สำหรับลูกค้าทุกคน
2. ที่นั่งที่ลูกค้าคนอื่นกำลัง "ล็อก" ระหว่างชำระเงิน ต้องขึ้นเป็นล็อกชั่วคราวและกดเลือกไม่ได้
   โดยล็อกมีอายุ 15 นาที หมดเวลาแล้วต้องกลับมาว่างอัตโนมัติ
3. ล็อกเกิดขึ้นตอนลูกค้ากดปุ่ม "ล็อกที่นั่ง" (ไม่ใช่ตอนคลิกเลือกที่นั่งเฉย ๆ — ไม่งั้นแค่กดดูเล่น
   ก็ไปกันที่คนอื่นแล้ว) และถูกปล่อยเมื่อกดยกเลิกหรือหมดเวลา
4. หน้าเลือกที่นั่งอัปเดตสถานะเองทุก 10 วินาที โดยไม่ต้องรีเฟรช
5. ถ้าที่นั่งถูกคนอื่นชิงไประหว่างทาง (ตอนกดล็อก หรือตอนส่งสลิป) ต้องเด้ง error ภาษาไทยที่บอกว่า
   ที่นั่งไหนหลุด ไม่ใช่เงียบ ๆ แล้วจองซ้ำ
6. การจองที่สำเร็จต้องบันทึกไว้ว่ากินที่นั่งใบไหนไปจริง ๆ

## การตัดสินใจ

- **ตาราง `seat_holds` ตารางเดียวเก็บทั้งล็อกชั่วคราวและที่นั่งที่จองแล้ว** แยกด้วยสองฟิลด์:
  `booking_id` ว่าง + `expires_at` ในอนาคต = ล็อกชั่วคราว · `booking_id` มีค่า + `expires_at` เป็น NULL
  = จองถาวร การใช้ตารางเดียวทำให้ "ที่นั่งนี้ว่างไหม" เป็นคำถามเดียว ไม่ต้อง join หลายที่
- **กันชนกันด้วย unique index `(concert_id, zone_id, seat_label)`** ไม่ใช่แค่เช็คก่อนเขียน
  เพราะสองคนกดล็อกพร้อมกันจะผ่านการเช็คทั้งคู่ (ต่างคนต่าง transaction มองไม่เห็นแถวที่อีกฝ่ายยัง
  ไม่ commit) ตัว index เป็นด่านสุดท้ายที่กันได้จริง — เจอ duplicate key ให้ตอบ 409
- **ล้างล็อกที่หมดอายุทิ้งใน transaction เดียวกับตอนจะล็อกใหม่** ไม่ต้องมี cron/background job
  แยก ที่นั่งจะถูกปล่อยตอนมีคนมาขอใช้ต่อพอดี และการอ่านสถานะก็กรองด้วย `expires_at` อยู่แล้ว
- **แยกของใครของมันด้วย `hold_token`** ที่ frontend สุ่มเก็บไว้ใน `sessionStorage` ต่อแท็บ
  (ลูกค้าจองได้โดยไม่ต้องล็อกอิน จะใช้ user id อย่างเดียวไม่ได้) endpoint อ่านสถานะจะ
  **ไม่ส่งล็อกของผู้เรียกเองกลับมาเป็น "ที่นั่งคนอื่น"** หน้าจอจึงไม่ทับสถานะตัวเอง
- **เวลาหมดอายุยึดจากเซิร์ฟเวอร์** — `POST /api/seat-holds` ตอบ `expires_at` กลับมา แล้ว frontend
  ค่อยคำนวณตัวนับถอยหลังจากค่านั้น กันนาฬิกาเครื่องลูกค้าเพี้ยนและกันกรณีรีโหลดหน้า
- **`createBooking` ต้องเปลี่ยนล็อกเป็นการจองภายใน transaction เดียวกับตอนสร้าง booking**
  ถ้าล็อกหลุดไปแล้วต้อง rollback ทั้งก้อน ไม่งั้นจะได้ booking ที่ไม่มีที่นั่งค้างในระบบ
- **`bookingPaymentApi.createBooking` ต้องเลิกกลืน error ทุกชนิด** ตอนนี้ `catch` ครอบทุกอย่างแล้ว
  ไปสร้าง booking ใน local store แทน (`frontend/src/api/bookingPaymentApi.ts:153-179`) ซึ่งแปลว่า
  ถ้าเซิร์ฟเวอร์ตอบ 409 ว่าที่นั่งถูกชิงไปแล้ว ลูกค้าจะยังเห็นว่า "จองสำเร็จ" — ต้องแยก
  "เซิร์ฟเวอร์ปฏิเสธ" ออกจาก "ต่อเซิร์ฟเวอร์ไม่ได้"
- **เลิกใช้ชุดที่นั่งจองปลอมใน `generateSeats()`** ที่นั่งทุกใบเริ่มต้นว่าง แล้วให้เซิร์ฟเวอร์
  เป็นคนบอกว่าใบไหนไม่ว่าง

## API ที่จะเพิ่ม

```
GET    /api/seat-availability?concert_id=&zone_id=&hold_token=
POST   /api/seat-holds
DELETE /api/seat-holds?hold_token=
```

- `GET` → `200` `{"data": {"taken": ["A3"], "held": ["B5"]}}`
  `taken` = จองสำเร็จแล้ว · `held` = คนอื่นล็อกชั่วคราวอยู่ (ไม่รวมล็อกของ `hold_token` ที่ส่งมา)
- `POST` body `{"concert_id","zone_id","seats":[],"hold_token"}`
  → `201` `{"data": {"expires_at": "2026-09-10T12:15:00Z", "seats": ["A1"]}}`
  → `409` `{"error": "...", "conflict_seats": ["A3"]}`
- `DELETE` → `200` `{"message": "..."}`
- `POST /api/bookings` (ของเดิม) เพิ่มรับ `hold_token` และเพิ่มกรณี
  `409` `{"error": "การล็อกที่นั่งหมดอายุหรือถูกคนอื่นจองไปแล้ว กรุณาเลือกที่นั่งใหม่"}`

## นอกขอบเขต

- **ผังที่นั่งจริงจากฝั่ง management** — ตาราง `venue_seat_zones` / `venue_seats` ยังว่างเปล่า
  (0 แถว ทุกคอนเสิร์ต) ถ้าต่อเข้าไปตอนนี้ลูกค้าจะไม่เห็นที่นั่งเลยและ flow จองพัง งานนี้จึงยังใช้
  ตาราง A1–E8 เดิม แต่ย้าย "ใบไหนว่าง" ไปอยู่ฝั่งเซิร์ฟเวอร์ทั้งหมด เมื่อวันหนึ่งมีผังจริงแล้ว
  เปลี่ยนแค่ตัวสร้างรายการที่นั่ง กลไกล็อกทั้งชุดใช้ต่อได้ทันที
- **เลขที่นั่งบนตั๋วที่ออกให้ลูกค้า** ยังเป็น `ZONE-01`, `ZONE-02` สังเคราะห์เหมือนเดิม
  (`booking_payment.go:217`) การเอาเลขที่นั่งจริงไปแปะบนตั๋วต้องแก้ทั้งขั้นตอนอนุมัติของฝ่ายขาย
  และหน้าบัตรของฉัน แยกเป็นงานของตัวเอง
- **ที่นั่งของการจองที่ถูกปฏิเสธ/ยกเลิก** ยังไม่ถูกปล่อยคืนอัตโนมัติในงานนี้ — ต้องออกแบบร่วมกับ
  flow คืนเงินของฝ่ายขายก่อน
- **Realtime แบบ WebSocket** — ใช้ polling 10 วินาทีพอสำหรับสเกลของโปรเจกต์นี้
