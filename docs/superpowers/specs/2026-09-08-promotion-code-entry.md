# Spec: เลือกโปรโมชั่น หรือกรอกรหัสโปรโมชั่น ในหน้าเลือกที่นั่ง

## ปัญหาปัจจุบัน

ใน `frontend/src/components/SeatSelection/OrderSummary.tsx` บล็อกโปรโมชั่นจะแสดง
`<Select>` **เฉพาะเมื่อ `eligiblePromotions.length > 0`** เท่านั้น ถ้าตัวกรองฝั่ง client
(`eligiblePromotions` ใน `frontend/src/pages/Customer/SeatSelection/index.tsx`) ไม่เจอโปรโมชั่น
ที่ตรงคอนเสิร์ต/โซน/ยอดขั้นต่ำ ลูกค้าจะเห็นแค่ข้อความ
"ยังไม่มีโปรโมชั่นที่ตรงกับยอดและโซนที่เลือก" และ **ไม่มีทางใส่รหัสโปรโมชั่นเองได้เลย**

ตัวกรองฝั่ง client จับคู่คอนเสิร์ตแบบ fuzzy (เทียบชื่อ) เพราะหน้าเลือกที่นั่งยังใช้
`eventsMap` ที่เป็น mock id `'1'`–`'4'` ซึ่งไม่ตรงกับ `concert_id` จริงในฐานข้อมูล
ทำให้โปรโมชั่นจริงหลุดจากรายการได้ง่าย

## สิ่งที่ต้องได้

1. บล็อกโปรโมชั่นในกล่องสรุปรายการ **แสดงเสมอ** ไม่ว่าจะมีโปรโมชั่นที่เข้าเงื่อนไขหรือไม่
2. ลูกค้าเลือกโปรโมชั่นจาก dropdown ได้ (รายการที่เข้าเงื่อนไข + รายการที่แลกด้วยโค้ดสำเร็จ)
3. ลูกค้ากรอกรหัสโปรโมชั่นเองได้ พร้อมปุ่ม "ใช้โค้ด"
4. โค้ดที่ใช้ได้ → ถูกเพิ่มเข้า dropdown และถูกเลือกให้ทันที ยอดชำระอัปเดตตาม
5. โค้ดที่ใช้ไม่ได้ → **ปฏิเสธ พร้อมบอกเหตุผลเป็นภาษาไทย** (โซนไม่ตรง / ยอดไม่ถึงขั้นต่ำ /
   คนละคอนเสิร์ต / ไม่พบรหัส) และยอดชำระไม่เปลี่ยน
6. เมื่อที่นั่งถูกล็อคแล้ว (`isLocked`) ห้ามแก้โปรโมชั่น เพราะยอดถูกยืนยันไปแล้ว

## การตัดสินใจ (จากการคุยกับเจ้าของงาน)

- **ตรวจโค้ดที่ Backend** ผ่าน endpoint ใหม่ ไม่ใช่จับคู่ในเบราว์เซอร์ — โค้ดที่ไม่ได้อยู่ใน
  ผลลัพธ์ของ `GET /api/customer/promotions` ก็ยังค้นเจอ และตรรกะส่วนลด/เงื่อนไขมีเทสต์ Go คุม
- **ปฏิเสธ + บอกเหตุผล** ไม่ใช่ยอมให้ข้ามเงื่อนไข
- **ติดตั้ง Vitest** ในฝั่ง frontend เพื่อคุม logic การจับคู่โปรโมชั่นและการคำนวณส่วนลด

## API ที่จะเพิ่ม

```
GET /api/customer/promotions/redeem
  ?code=SAVE15
  &concert_id=2
  &concert_name=Riverside Sound Festival
  &zone_id=B4
  &zone_label=โซน B
  &total=4500
```

- `200` → `{"data": {"promotion": <customerPromotionDTO>, "discount_amount": 675}}`
- `400` → `{"error": "กรุณากรอกรหัสโปรโมชั่น"}` (code ว่าง / total ไม่ใช่ตัวเลข)
- `404` → `{"error": "ไม่พบรหัสโปรโมชั่นนี้ หรือโปรโมชั่นนี้ใช้งานไม่ได้แล้ว"}`
- `409` → `{"error": "<เหตุผลที่ใช้ไม่ได้>"}`

หมายเหตุ: `findCustomerPromotions` กรองโปรโมชั่นที่หมดอายุ/โควตาหมด/ยังไม่อนุมัติ ออกไปก่อนแล้ว
ดังนั้นโค้ดที่หมดอายุจะได้ `404` (ข้อความครอบคลุมทั้งสองกรณี) ไม่ใช่ `409`

## นอกขอบเขต

- ไม่แตะการตัดโควตา (`used_quota`) ตอนจ่ายเงินจริง — ระบบยังจำลองการจ่ายอยู่
- ไม่แก้ระบบโปรโมชั่นฝั่งพนักงาน
- ไม่แก้ให้หน้าเลือกที่นั่งเลิกใช้ `eventsMap` mock
